# 步骤 8：发布闸门

只有用户明确要求发布、配置 CI 或处理 Pages 时才读本步骤。普通提交和推送不触发发布。

## 顺序

1. 读 `references/publish-gate.md`，按其中固定顺序执行，不跳步。
2. 确认发布前置条件：版本号、标签约定、CI workflow、凭据与权限、目标环境。
3. 先跑与 CI 同款的本地检查；本地失败不进入发布。
4. 需要打标签时，只在用户要求且版本已确认后创建；不擅自推标签或触发发布。
5. 发布后读回：工作流结论、部署 URL、关键内容；读回不符就停止并报告。

## 边界

- 不改仓库设置、secrets、分支保护或域名；这些需要单独授权。
- 不用「工作流已触发」代替「发布成功」；成功以读回结果为准。
- Pages 细节见 `references/github-pages.md`；Actions 权限与并发见 `references/ci.md`。
- npm 等包发布涉及凭据与不可逆动作：没有明确授权和可信来源时只报告，不执行。

## 记录

记下发布动作、工作流结论、读回 URL/内容；步骤 9 的 `mode`：做了 Pages/发布读回填 `pages`，只完成推送填 `push`，没有执行远端动作填 `skipped`；`checks.readback` 按真实读回填。
