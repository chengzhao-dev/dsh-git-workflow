# 步骤 3：跑项目门禁

提交之前，用项目自己声明的入口验证改动。本地全绿不等于远端发布成功，但本地失败一定不能提交。

## 执行

- 优先使用 `CONTRIBUTING.md`、`AGENTS.md` 或 CI 中声明的同款命令（例如 `npm test`、`npm run check`、`cargo test`）。
- 项目没有门禁时，至少运行：

```bash
git diff --check
git diff --cached --check
```

- 只运行与本次改动相关、且项目已声明的检查；不要临时安装新工具或改项目脚本。
- 需要联网、登录或写入项目外目录的检查，先确认权限；无法执行就报告，不伪造结果。

## 失败时

1. 在本地复现并修因，不盲目追加提交触发 CI。
2. 修因超出授权范围时停下来报告，让用户决定。
3. 记录实际运行的命令与结论，步骤 9 的回执要如实填写 `project` 检查。

## 不做什么

- 不把「本地检查通过」说成「已发布」。
- 不用跳过 hooks、忽略测试或改 CI 配置的方式让门禁变绿。
