# 步骤 2：定范围

把「用户要求的交付」翻译成可核对的清单，避免提交时顺手带上别的东西。

## 清单

- **提交路径**：用户点名的文件或目录，逐个列出。未点名的改动不进入本次暂存。
- **目标分支**：当前分支是否就是要交付的分支；不在 detached HEAD。
- **远端**：`git remote -v` 是否指向预期仓库；首次推送才建立 upstream。
- **动作边界**：用户只要求 commit、push、PR、Issue，还是也要求发布？未要求的动作不做。
- **提交分组**：按「出错时希望回滚到哪」切分，每组可独立回滚。没有固定提交数量；不为拆分而拆分，也不把不可运行的中间状态单独提交。

## 先看差异

```bash
git status --short
git diff --stat
git diff --name-only
```

工作区里有用户既有的未提交改动时，明确区分「本次授权范围」与「用户自己的改动」。无法区分就问，不把两者混进同一个暂存区。

## 范围变化

执行中范围扩大（例如发现必须改另一个文件）时，先向用户说明并取得同意，再更新清单；不要默默扩大。
