# 步骤 4：写提交信息并调用 `git_commit_check`

提交信息先按官方结构写，再叠加本项目的扩展规则；两步都通过才算通过。

## 官方结构

```text
<type>(<scope>)!: <description>

<body>

<footer>
```

- 标题一行；`type` 必填，`scope` 可选，`!` 紧贴冒号，冒号必须是英文半角且后跟**一个空格**。
- 正文与 footer 各自用一个空行分隔；没有正文或 footer 时可以省略。
- `BREAKING CHANGE` / `BREAKING-CHANGE` 必须全大写；`!` 可以单独表示破坏性变更。
- footer 的 token 用 `-` 连接单词，值前用 `: ` 或 ` #`。

## 类型

`feat`、`fix`、`build`、`chore`、`ci`、`docs`、`style`、`refactor`、`perf`、`test`、`revert`。一次提交只用一个类型；项目需要额外类型时通过工具的 `extra_types` 传入，不擅自发明。

## 项目扩展

默认规则（项目文档更严时以项目为准）：

- 描述至少包含一个汉字，不超过 50 个字符，结尾不加句号；技术专名保留英文。
- 写 scope 时用小写 kebab-case。
- 禁止 `Co-authored-by`、`Signed-off-by` 以及 `Cursor` / `cursoragent` / `Made with Cursor` / `Generated by Cursor` 等第三方署名。
- 项目明文要求 DCO 等 trailer 时，才把 token 放进 `allowed_trailers`；不要用放行来掩盖 AI 署名。

## 调用检查

在提交前调用 `git_commit_check`：

```json
{
  "message": "feat(parser): 添加提交信息校验",
  "require_chinese": true
}
```

- `message` 模式只检查信息本身，不核对身份；不要同时传 `author`/`range`/`all`，工具会报错。
- 身份（author 与 committer）在步骤 5 提交后用 `range` 模式核对；通过前不推送。
- `require_chinese` 默认 `true`；项目明确允许英文描述时才传 `false`。
- 只检查信息时传 `message`；要检查已有提交时省略 `message`，用 `range`（默认下一次 push 的范围，不是全部历史），只有调用方明确要求全历史才传 `all: true`。
- 工具只读 `git log`，不会暂存、提交或推送。

## 失败处理

- `invalid-header`、`unknown-type`、`missing-body-blank-line`：改格式，不绕过。
- `description-not-chinese`、`description-too-long`、`description-trailing-period`、`invalid-scope`：改描述或 scope，或确认项目规则后调整工具参数。
- `forbidden-trailer`、`forbidden-cursor-*`：删掉第三方署名；不要用 `allowed_trailers` 放行 AI 标记。
- 非 Git 目录或身份无法核对：停止并报告，不提交。

检查通过后，把**同一份完整信息**写入临时文件，供步骤 5 使用；不要在这里用 `-m` 重新拼一遍。
